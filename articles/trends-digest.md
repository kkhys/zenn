ここ最近、AI まわりの動きが速すぎて、情報収集が追いつかなくなってきました。

そこで、自力で情報を集めるのをやめました。正確に言うと、集めて選んで要約するところまでを AI に任せ、自分は毎朝コーヒーを飲みながら出来上がったページを読むだけにしました。

そのために作ったのがこのサイトです。

https://trends.kkhys.me

いくつかのサイトからその日のトレンドを集め、要約とコメント欄の反応を付けて、日ごとのページとして公開しています。生成しているのは Claude Code のスキルで、公開先は Astro の静的サイトです。どちらもコードは公開しています。

https://github.com/kkhys/claude-code-marketplace/tree/main/plugins/base/skills/creating-trend-digest

https://github.com/kkhys/me/tree/main/apps/trends

この記事では使い方や作り方の手順というより、なぜこういう形にしたのか、何をやめて何を残したのかを書き留めておきます。

## 情報収集がいつのまにか作業になっていた

長らく Feedly に購読フィードをまとめ、タイトルを流し読みして、気になったものを開くというのを続けてきましたが、ここ 1〜2 年で明らかに回らなくなりました。

まず量です。AI まわりは動きが速く、新着がすぐにたまります。タイトルだけで判断するので、開いてみたら思っていた内容と違った、ということが頻発していました。

次に長さです。生成 AI の影響なのか、無駄に長い記事が増えました。要点は 3 行で済むのに、どうでもいい前置きと補足で数千字になっていることも少なくありません。読むべきかどうかを判断するためだけに長い文章を読むのは本末転倒です。

タイトルを見て開き、違ったので閉じるという作業を繰り返すのはできれば避けたいです。

なお、僕は SNS を情報収集には使っていません。情報がスピーディーに流れるのは SNS だと分かってはいるのですが、役に立つ投稿にたどり着くまでに関係のない投稿や広告を大量に見ることになることも少なくありません。長く滞在させるように設計された場所で情報収集をするのは、時間の使い方として割に合わないと思っています。

## 集めるのをやめて、読むだけにする

考え方は単純で、情報収集を「集める・選ぶ・要約する」と「読む・考える」に分け、前半を AI に任せることにしました。

毎朝、Claude Code でスキルをひとつ実行します。すると、いくつかのサイトからその日の上位記事を取ってきて、1 件ずつ要約とコメント欄の反応のまとめを付けます。それから、その日の見出しとまとめを書いて静的サイトとして公開するところまで実行してくれます。僕は出来上がったページを読むだけです。

ポイントは、リンクを開く前に判断できる材料がそろっていることです。判断材料が表示されていれば、ページを開くかどうかを迷わず決められます。

## ページに載せているもの

![Trend Digest のトップページ。その日の見出し、まとめ、ハイライトが並んでいる](/images/trends-digest/01.png)
*ページの上部。見出し 1 行とまとめ、ハイライト 3〜5 件*

大事なものほど上に置いています。時間のない朝は上のハイライトだけ読んでいます。

その下に、グローバルと日本の順で、ソースごとに上位 10 件が並びます。1 件ごとに順位とタイトル、1〜2 文の要約、折りたたみのコメント要約（または記事要約）、それにスコアや興味の星、カテゴリ、反応の数といった補足情報が付きます。

海外記事のタイトルは日本語に訳し、原題は下に小さく添えました。訳だけだと検索や引用ができず、原題だけだと読みにくいので両方載せています。折りたたみも同じ考えで、一覧で見せるのは 1〜2 文にとどめ、詳しく知りたければ開く形です。

![記事の行。コメントの要約を開いた状態](/images/trends-digest/02.png)
*記事ごとの行。「コメントの要約」を開くと、記事の概要とコメント欄の論点が 2〜3 段落で読める*

毎朝読むものなので、目立つ装飾は入れずにシンプルな UI にしています。

### 順位はスコアだけ、興味は星だけ

表示順はスコアだけで決めます。スコアはそのソース内での相対的な盛り上がりと新しさから独自に計算したもので、自分の興味は入っていません。興味は星（★1〜3）としてタイトルの下に付くだけで、並び順には影響しません。

以前は興味に応じて倍率をかけていたのですが、関心の高いテーマが上位を独占して一覧が偏ってしまうのでやめました。一覧は世の中の話題をそのまま並べ、自分向けの調整は星とハイライトの選び方だけに使っています。

### 既出は減点しない

過去の日にも載っていた記事には既出バッジが付きますが減点はしません。何日も上位に残る記事は、それだけ本当に話題になっているということだからです。

![アーカイブページ。日ごとの見出しが並ぶ](/images/trends-digest/03.png)
*アーカイブ。見出しを流し読みするだけで、その週に何が起きたかがだいたい分かる*

## 記事より、コメント欄の要約

このサイトでいちばん気に入っているのは、記事そのものの要約よりも反応の要約の方かもしれません。

Hacker News、Lobsters、Reddit、はてなブックマークの上位記事は、コメント欄の上位コメントも取ってきて「コメントの要約」として 2〜3 段落にまとめています。1 段落目にその記事が実際には何なのかを、2 段落目以降にコメント欄で出た主な論点と意見の割れ方を書きます。

それは本当に新しいのか、以前からある話の繰り返しなのか。記事の主張に穴はないのか。実際に試した人はどう言っているのか。こういうことは、コメント欄にしか書いてありません。

要約の書き方にはルールを設けています。事実だけを書き、「おすすめ」「注目」「チェックしよう」のような言葉は使わないようにしています。コメントの意見は「〜という指摘」「〜との報告」のようにコメントした人の意見として書き、AI 自身の意見にはしていません。AI に任せるのは何が起きたかを整理するところまでで、どう思うかは自分で考えたいからです。

## 仕組み

技術の話を少しだけ。構成は「集める」「書く」「ビルドする」の 3 層です。

![集める・書く・ビルドするの 3 層パイプライン。Python が 10 のソースを並列取得して raw.json に落とし、Claude が興味プロフィールを見ながら選別・要約し、Astro が zod で検証してビルドし Cloudflare Pages へ配信する](/images/trends-digest/04.png)
*[diagram-design](https://github.com/cathrynlavery/diagram-design) を使って作成しました。この Skills も [Trend Digest](https://trends.kkhys.me) で見つけたものです。*

集めるのは Python スクリプトです。標準ライブラリだけで書いてあり、10 のソースを並列に取りに行きます。ひとつの API が落ちても他は続き、落ちたソースはサイト上に注意書きとして出るだけで、実行は止まりません。取ってきた記事にスコアを付け、既出の記事を記録し、コメント or 本文を添えて `raw.json` に書き出します。

```python
base_score = round(100 * (0.75 * engagement_pct + 0.25 * freshness))
# freshness: <6h 1.0 / <12h 0.9 / <24h 0.75 / <48h 0.55 / それ以降 0.35
```

書くのは Claude です。`raw.json` と後述する興味プロフィールを読み、除外テーマの記事を落として星とカテゴリを付け、タイトルを訳して要約を書き、最後に見出しとまとめとハイライトを組み立てます。

結果は 1 日 1 ファイルの JSON です。Claude 自身には記事を取りに行かせません。スクリプトが取ってきた範囲だけで書きます。これは結果を安定させるためでもあり、AI が勝手に Web を見に行って時間を使わないためでもあります。

ビルドするのは Astro です。JSON は Git にコミットされ、zod のスキーマで検証されてから静的 HTML になり、Cloudflare Pages に配信されます。データが全部 Git に残るので、どのテーマが何日続いたかといった集計もあとからできます。

## 自分好みに育てていく

どの記事を拾ってどれを落とすかは、コードではなく手元のテキストファイルで決まります。その中心が、自分の興味のあるテーマを並べた興味プロフィールです。

```md:~/.claude/trend-digest/profile.md
## 興味テーマ

- high: AIコーディングエージェント・開発ツール (Claude Code, LLM活用開発, エージェント設計)
- high: LLM・生成AIの新モデル/新技術動向
- mid: セキュリティ (特にAI×セキュリティ、Webセキュリティ)
- mid: JavaScript / TypeScript / Webフロントエンド
- mid: エンジニアのキャリア・組織論
- low: ガジェット・ハードウェア

## 除外テーマ

- 政治・芸能ゴシップ
- 暗号通貨の価格変動の話題

## フィードバックログ

- 2026-08-12: はてなブックマークに tech と関係ない記事が多い → hatena_categories から "all" (総合) を外し "it" のみに
```

このファイルが星の基準であり、除外の基準であり、ハイライトを選ぶ基準でもあります。ただの Markdown なので手で書き換えてもいいし、ダイジェストを読んだあとに Claude Code へ「Rust は興味ない」「この手の記事はもういい」と言えば、Claude がプロフィールを書き換えてフィードバックログに日付付きで残します（ADR 的に運用する想定です）。

プロフィールのほかにも、ソースごとの表示件数や購読する subreddit を決める設定ファイルがあり、その日限りの引数も渡せます。「セキュリティ中心で」「件数少なめ」と渡せば、その日のダイジェストだけが変わり、プロフィールは変わりません。

```text
/base:creating-trend-digest セキュリティ中心で
```

使うほど自分に合ってくる、という感覚です。ニュースアプリの「おすすめ」や他人が作った情報収集サイトは自分で調整できませんが、これは設定が全部手元のテキストファイルにあります。

## 弱点

いいことばかり書いてきたので、見えてきた弱点も挙げておきます。

要約は AI が書いているので、誤読も言い過ぎもありえます。本文は一定の長さで切って渡しているので、記事の末尾にある結論を落とすことも当然ながらあります。

それに、要約はあくまで読むかどうかを決めるための材料で、読んだことにするための代わりではありません。ここを取り違えると、要約を読んで分かった気になり、手を動かさなくなってしまいます。技術記事は特に注意が要ります。

見えなくなるものもあります。除外テーマに入れた話題は目に入らないし、10 のソースに載らない話題は永遠に来ません。順位に興味を反映させないことで偏りは抑えていますが、入り口を 10 に絞っている以上、偶然の出会いは減ります。

また、コメント要約は目立つ意見に偏ります。Hacker News の上位コメントには英語圏のエンジニアの偏りがあり、はてなブックマークのコメントは短めで極端な反応が多いです。反応の要約はその場の雰囲気であって世論ではないことを頭に入れておく必要があります。

あとは、手動なので忘れることもあります。時間も利用料の枠もそれなりに使いますし、実行し忘れると、あとから作れるソースは限られます（さかのぼって取れるのは Hacker News と Hugging Face Daily Papers だけ）。

## 今後やりたいこと

JSON が全部残っているので、どのテーマが何日続いたか、どのソースが先でどのソースが後か、といった可視化はやってみたいです。グラフにすると面白そうですね。

いま 1 日あたり 100 件近く載っていますが、ハイライトだけで足りる日も多いので、星 3 だけ、既出を除いた新しい記事だけ、といった絞り込みをその日の気分で選べるようにしたいというのもあります。

ソースの取得部分を差し替えれば、経済でも科学でも同じものが作れる構造にしてあるので、経済ニュース版は近いうちに試してみたいです。

## さいごに

やったことは、情報収集を「集める」と「読む」に分けて、前者を AI に任せただけです。技術的には Python のスクリプトと Markdown の指示書と JSON と静的サイトで、目新しいものはありません。

それでも、朝の過ごし方は変わりました。タブを開いたり閉じたりする時間がなくなり、コーヒー 1 杯の間にその日の話題が頭に入るようになりました。また、Web サイトとして公開しているので買い物の待ち時間などにスマホでサクッと確認できる点も気に入っています。

ここ最近、AI の進化が速い時代に、速さで追いかけるのは無理があると思うようになりました。集めるのは AI に任せて、自分は読むことと考えることに時間を使う。この形でしばらく続けてみようと思います。
